# 三分钟逐秒演示脚本

目标：先证明采购审核结果，再回答“怎么做到”。全部数据均为模拟。

## 0:00–0:30｜原始资料

**0:00–0:06**

停在「原始资料」页顶部。

> 这是一个电子料 BOM 报价审核台。先说明：全部是模拟数据，没有接真实客户、供应商或生产系统。

**0:06–0:16**

指 BOM 第 1–4 行。

> 同一颗 MCU 有两种写法，LDO 重复，有的缺品牌，还有疑似错料号。人工需要逐行辨认。

**0:16–0:25**

依次点 CSV、邮件正文、JSON。

> 四家回复格式不同，币种、含税口径、MOQ、库存、交期和有效期也不同。这是报价人员真正费时间的地方。

**0:25–0:30**

指向「主路径：真实 OMA + DeepSeek」的已就绪标记，点击「运行真实 OMA 审核」。

> 现在用真实 OMA 和模型 API 读取这些模拟资料；失败会明确停下，不会偷偷换成固定答案。

## 0:30–1:10｜运行处理

**0:30–0:45**

看处理页的固定流程。

> BOM 分析和四家供应商读取并行执行；等前置结果完成后，再由独立角色复核证据。界面不展示 Agent 聊天。

**0:45–0:58**

指向「应用」阶段和固定假设。

> 模型负责多格式读取和风险发现；价格、汇率、税费、库存、交期、MOQ 和资质比较仍由显式业务规则完成。

**0:58–1:10**

完成后指执行凭证，点击「打开采购审核稿」。

> 这里记录本次 provider、model、运行标识和实际角色。结果不是自动采购，而是负责人审核稿。

## 1:10–2:00｜推荐、覆盖与风险

**1:10–1:25**

指四个指标卡。

> 26 行原始 BOM 合并成 24 个采购项。22 个有可追溯报价，覆盖率 91.7%；16 个满足核心约束，6 个必须人工确认，2 个没有报价。

**1:25–1:38**

指第一行 STM32。

> 最低价没有被推荐：一条资质待核，另一条交期 35 天。推荐项虽然不是最低价，但满足当前交期、库存和资质规则。

**1:38–1:50**

点击「待确认」。

> 替代料未工程确认、库存只能部分覆盖、过期、MOQ、错料号和资质风险都没有被藏起来。

**1:50–2:00**

点击「无报价」。

> 找不到报价就保留无报价，不会为了填满表格而编造供应商和价格。

## 2:00–2:30｜来源证据

**2:00–2:05**

回到「全部」，打开 STM32 第一行「查看来源」。

**2:05–2:18**

指推荐理由和最低价未采用解释。

> 每个判断能解释：为什么推荐，为什么没有选最低价。

**2:18–2:27**

指原始报价、归一化成本、库存、MOQ、交期、Date Code、渠道和原文证据。

> 负责人能回到具体模拟文件和位置核对，不需要只相信模型总结。

**2:27–2:30**

演示一次「人工改为此供应商」。

> 人可以改选；这里只更新审核稿并写入审计，不发邮件、不下单。

## 2:30–2:50｜人工审批

**2:30–2:36**

关闭抽屉，点击「负责人审批」。

**2:36–2:44**

展示批准、驳回、补充询价，填写备注。

> 采购负责人保留最终决定权。替代料仍必须由工程确认。

**2:44–2:50**

确认审批并进入导出。

> 审批后才进入交付物导出。

## 2:50–3:00｜导出与真实试点

**2:50–2:55**

展示四个导出卡片。

> 客户报价草稿、内部采购审核表、异常清单和审计记录都保留模拟和执行来源标记。

**2:55–3:00**

指右下角能力边界。

> 下一步不接生产系统，只要 3–10 份脱敏历史 BOM 和原人工结果做回放；先验证真实差异，再决定是否试点。

## 现场备用路径

只有实时 API 明确失败或网络不可用时，演示者才点击「明确切换离线回放」：

> 真实调用刚才没有完成，我现在主动切换到离线回放，继续展示交付形态。接下来的结果不是本次模型调用，页面和导出都会保留这个标记。

如果内置包仍是 `FIXTURE_BASELINE`，必须再说：

> 这是确定性 fixture 基线，不是此前真实 OMA 运行的捕获。

## 演示纪律

- 不说“已经帮助客户节省了多少时间”。
- 不说“报价准确率”“成交提升”“毛利提升”，因为没有真实回放数据。
- 不从 OMA、多 Agent 或架构开场；先让对方看到业务资料和审核结果。
- 不把离线回放说成本次实时调用。
- 不把替代料建议说成工程认证。
- 对方要求真实数据时，只提客户授权、脱敏、边界内历史回放。
