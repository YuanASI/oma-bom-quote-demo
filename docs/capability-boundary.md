# 演示内容与真实能力边界

## 一句话

这个 Demo 证明：混乱 BOM 和多格式供应商回复，可以形成有规则、有来源、有人审、可导出的采购审核稿。

它不证明：真实客户已经节省时间、减少错误、提高毛利或提升成交。

## 三层能力必须分开

| 层 | 当前实现 | 能证明什么 |
|---|---|---|
| 真实 OMA + 模型 API | 已实现固定 `runTasks()` DAG；2026-07-23 已通过真实 DeepSeek E2E | 有 Key 且页面显示 `LIVE RESULT` 时，证明本批模拟资料确实经过 OMA 与模型处理 |
| 离线回放 | 已实现；当前 bundled 包为 `LIVE_OMA_CAPTURE` | 稳定重放一次已验证的真实 OMA 模拟数据结果；不证明本次打开页面时发生模型调用 |
| 确定性业务规则 | 已实现并自动化测试 | 汇率、税费、约束比较、推荐、审批和导出可重复检查 |

没有 Key 时可以使用该捕获包演示，但只能说“离线重放已验证的历史捕获”，不能说“本次发生了模型调用”。真实 provider 验收记录见 [`validation-log.md`](validation-log.md)。

## 当前真实可运行

- 查看 26 行模拟 BOM；
- 读取四家虚构供应商的 CSV、自然语言邮件正文和 JSON；
- 真实执行 OMA 固定 DAG：1 个 BOM 分析、4 个并行供应商读取、1 个依赖式证据复核；
- 用结构化 schema 校验模型输出；
- 用源文件原文、料号、价格、置信度和未解决字段校验每条模型报价；
- 归一料号、合并重复项、保留原 BOM 行；
- 用固定模拟汇率和税率统一口径；
- 比较价格、库存、交期、MOQ、有效期、Date Code、渠道和资质；
- 给出推荐、理由、最低价未采用解释和来源；
- 人工改选、标记补询、批准、驳回和填写备注；
- 本地导出客户报价草稿、采购审核表、异常清单和审计记录；
- 在没有 Key 时使用明确标记的离线回放。

## 当前明确没有

- 没有接入真实 ERP、WMS、CRM、报价库、邮箱或供应商门户；
- 没有真实客户、供应商、报价、库存或联系人；
- 没有发送邮件、消息、表单或询价；
- 没有自动下单、采购执行或付款；
- 没有替代料工程认证；
- 没有登录、权限、多租户、支付或生产级数据治理；
- 没有生产级通用 Excel `.xlsx` 解析；表格 fixture 使用 CSV；
- 没有真实客户收益、准确率、报价时长或成交数据；
- 当前 `LIVE_OMA_CAPTURE` 只对应这一组模拟 fixture 和一次已记录的 OMA + DeepSeek 运行，不代表任意新 BOM 都会得到相同覆盖率或结果。

## 关键口径

| 页面说法 | 实际含义 |
|---|---|
| 覆盖率 91.7% | 24 个归一化采购项中，22 个至少有一条可追溯模拟报价；不等于可直接下单 |
| 已匹配 16 | 至少一条报价满足当前核心规则；仍需负责人复核真实库存和有效期 |
| 待确认 6 | 有报价但存在必须人工关闭的风险 |
| 无报价 2 | 四份模拟回复中无匹配项；系统没有补造价格 |
| 推荐供应商 | 按当前显式规则形成的审核建议，不是采购决定 |
| 目标价毛利 | 模拟目标价与归一化成本的提醒，不含真实物流、资金、关税或账期 |
| 本次真实执行 | `isLiveModelCall=true` 且有 OMA run id、角色、任务和 token 记录 |
| 离线回放 | 本次没有模型调用；必须同时显示 replay id 与 capture kind |

## 替代料声明

替代料只是一条待工程审核建议。没有规格书比对、样品测试、认证或工程签字，绝不构成替代料认证。

## 真实价值需要什么证据

只用客户明确授权的脱敏历史资料回放：

1. 3–10 份已结束 BOM；
2. 当时的脱敏供应商回复；
3. 人工最终结果和已知异常；
4. 收件到首轮报价的真实耗时；
5. 业务负责人和一线报价人员共同复核差异。

只有回放后才能讨论时间、错误、覆盖、毛利和成交影响；回放前不对外给收益数字。
