# 从 Demo 进入脱敏历史数据回放

目标不是“接系统”，而是先回答一个更小的问题：这套审核形态在客户真实历史数据上，是否比当前人工流程更快、更完整或更容易复核？

## 阶段 0｜先定边界，不收数据

30 分钟流程拆解，参与者：

- 采购或 BOM 报价负责人 1 名；
- 一线报价人员 1 名；
- 必要时工程或质量代表 1 名。

先确认：

- 数据能否脱敏；
- 哪些字段不得离开客户边界；
- 谁批准样本使用；
- 数据保存多久、如何删除；
- 哪些步骤只读，哪些动作明确禁止。

没有边界共识，不进入下一步。

## 阶段 1｜选择 3–10 份已结束样本

只选已完成、结果可回看、复杂度有代表性的历史 BOM。每份至少包含：

- 脱敏客户 BOM；
- 当时收到的脱敏供应商回复；
- 最终人工采购/报价结果；
- 已知错料、漏报、退回或补询记录；
- 收件、首轮报价和最终报价时间戳。

不需要实时账号，不需要供应商密码，不需要生产写权限。

## 阶段 2｜冻结基线与指标

回放前共同定义，不在结果出来后挑指标：

| 指标 | 定义 |
|---|---|
| 首轮整理时间 | 收件到形成可审核稿的人工净耗时 |
| 采购项覆盖率 | 有可追溯报价的归一化采购项 / 全部归一化采购项 |
| 关键异常召回 | 历史已知异常中，被回放结果明确标出的比例 |
| 误报项 | 系统标为异常但负责人认定无需处理的数量 |
| 人工修改率 | 负责人改选供应商或改状态的采购项占比 |
| 可追溯率 | 推荐能够回到原始文件和位置的采购项占比 |

这些是待测指标，不是当前 Demo 的成绩。

## 阶段 3｜只读回放

- 客户数据留在约定边界内；
- 先冻结当前人工结果和确定性规则基线；
- 若允许模型调用，再单独运行真实 OMA + 指定模型并记录 provider、model、run id、提示版本和输入哈希；
- 若数据不得离开客户边界，就在客户可接受的模型或本地模型环境运行，不默认发送到 DeepSeek；
- 允许人工标注料号映射和业务规则；
- 不调用真实供应商，不发消息，不下单；
- OMA + 模型结果、离线回放和纯规则基线分开统计，不能混算。

## 阶段 4｜逐项差异复核

对每个采购项记录：

- 与历史人工结果一致还是不一致；
- 不一致来自数据缺失、规则错误、料号歧义还是人工业务判断；
- 是否需要新增显式规则；
- 哪个角色有最终决定权；
- 是否存在无法安全自动化的步骤。

输出一份“差异账本”，不只给总分。

## 阶段 5｜Go / Iterate / Stop

### Go

- 至少一个真实基线指标有可复现改善；
- 负责人愿意继续提供同类样本；
- 数据边界和人工 gate 清晰；
- 现有系统没有直接覆盖。

### Iterate

- 痛点真实，但料号映射或规则覆盖不足；
- 先补领域规则和样本，不急着接生产系统。

### Stop

- 人工更快且错误很少；
- 痛点主要是供应商等待或稀缺货源，资料整理不是瓶颈；
- 现有报价库已闭环；
- 客户无法提供合规样本或流程 owner；
- 改善不影响任何经营结果。

## 回放后的最小交付

1. 基线与回放指标表；
2. 逐项差异账本；
3. 数据与动作边界图；
4. 可自动化 / 必须人工 / 暂停三类清单；
5. 是否值得进入小范围试点的书面结论。
